## 2. 我的修正
- 「T0 +87／+110」只能當「若 T0 為真」的損失量級，不能支持 τ。「minimax 選刪」取決於未知的 τ。
- 「不改成不刪、保留現行」過強。丙在預設預算下，10／12 點場景有 80%／100% 在 t=0 就刪點。丁指出速度錯時白刪且不復原。該保留的是「只刪到來得及」的原則，要改的是時機與資訊（實測速度、每輪重算）。我測的「最後一刻才刪」不等於丙、丁的每輪可行性檢查，不可外推。
- 「字面是 T1」過強。rulebook.txt:317 只否定完成回報分，4.2.5（:588-590）只說逾時程式被關閉。應寫「字面沒說 T0」。
- 每場 sd 13–17、SE 4–5% 來自 scenarios.py 的猜測分布。若 10 次條件跨提交固定，配對比較能分辨更小的差異。

## 3. 盲點
- 可重複提交：期限 2027-01-20 前可重交（rulebook :467-469），只有 FINISHED 能提交（:493-495）。目標是多次嘗試中的最佳一次，探針很便宜；真風險是期限前沒有可交的 FINISHED。每日跑次數配額 `未驗證`，它決定能做幾個探針。
- 逾時可能是第三種世界：程式被關閉（:588-590），若因此整份程式變 FAILED 而不能提交，逾時就是閘門事件，支持保留 margin。`未驗證`，一場故意逾時就能看狀態。
- 「長時間不動則提早結束」（:592-594）可能與每點 8 s 懸停衝突，門檻未定義。第一小時看有沒有提早結束。
- 探針價值有條件：先用實測速度校準，若之後很少觸發刪點，A/B 與 T0/T1 探針就不必花次數。Time Bonus 曲線可由正常跑的完成時間自然變異擬合，不需專門探針。
- 工程優先序看 P(失敗)×損失：零分事件（Goal 不在清單、例外、閘門）重於任何 ±10% 的調參。

## 4. 建議採納
1. 規則世界旗標（Goal 需全點、逾時保留 Pt_check，可加逾時＝FAILED）＋實測速度＋每輪重算＋可還原刪點。驗收：真速 {0.05,0.1,0.2}×{A,B}×{T0,T1} 表中，與 oracle 速度版差 ≤10%，Goal 到達率不低於它；只有名次不變的結論進 README 第 5 節。
2. 保底層：Goal 不在清單時降級、run_mission 用 try/finally 呼叫 mission_finish、自判閘門加校準模式。驗收：三個新測試（缺 Goal 仍跑完並 finish；例外 Robot 的 finished_at 非 None；BlindRobot 仍送通知並記錄自判 Lv）。
3. 上機劇本加飛行記錄器，順序：範本與配額，兩次相同提交看條件是否固定，正常跑校速，視刪點是否觸發才跑 A/B、T0/T1。驗收：log 可逐段對上 JSON（秒數、nav stamp、各點 Lv 對 level）；FakeRobot log 往返還原參數誤差 <10%。
